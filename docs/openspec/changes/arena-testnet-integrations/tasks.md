## Observability and recovery

- [x] Persist finalized indexer cursors, block hashes and deduplication keys and reconcile chain state after restart.
  - Verified by fixture tests (`agent/test/indexer/{engine,reorg-restart,retention,wiring}.test.ts`; not live evidence). `agent/src/indexer/`: injectable `BlockSource`, validated NEP-297 parser that authenticates the receipt executor before parsing and handles u64 losslessly, pure deterministic projection, atomic single-snapshot store with single-writer lock, dedup keyed by network|contract|receipt|logIndex|itemIndex, and restart recovery that verifies source identity/hash/ancestry and restores the last persisted health before advancing. Fails closed on corrupt state; never silently resets.
  - Retention (#109, D31): finalized blocks older than `INDEXER_RETENTION_DEPTH` (default 10000, an agent choice) are folded into a hashed checkpoint labelled as a summary and dropped, so block storage cannot wedge. Provisional blocks, the journal with every dedup key, and any block holding conflict or integrity evidence are never pruned. Restart re-verifies the checkpoint (event commitment against the journal, parent link to the first retained block, and the source hash at the checkpoint height when the source still serves it).
  - Event coverage (#109): every NEP-297 event emitted on main under `valtrum`, `valtrum_backing` and `valtrum_payout` is projected (backing approval and trust, late deposit with refund address, suspension and custody attestation, payout signature and state events) or reported as `unknown_event` with a degraded status. Companion contracts emit one data object, not an array; both shapes are read.
  - Wiring (#109): `agent/src/main.ts` injects the indexer behind `INDEXER_ENABLED=true` (recorded chain file only, no live source exists) and the audit report archive behind `AUDIT_REPORT_ARCHIVE_ENABLED=true`; both are off by default.
  - Not verified: a live NEAR archival/indexing provider (source identity, finality and reorg evidence); the live-adapter integration remains open.
- [x] Detect reorgs, retract provisional projections and suspend affected confirmations until finality is restored.
  - Verified by fixture tests (`engine.test.ts`, `reorg-restart.test.ts`). The engine reconciles provisional blocks by hash, rolls back orphaned effects to the common ancestor, replays the canonical branch once and promotes finality only along the source-declared finalized chain. A retraction persists a reorg suspension (`state.reorgSuspension`): `confirmations()` reports no finalized credits and the status stays non-healthy until finality reaches the highest retracted height, also across a restart. A conflict at or below the finalized boundary requires reconciliation instead of rewriting finalized state. Retraction is read-only and never touches custody or payouts.
  - Not covered here: suspension of real custody and payout confirmations belongs to the backing and payout services (the backing contract suspends on `reorganize_receipt`, and the indexer projects `asset_suspended` and `asset_resumed`).
- [x] Display entitlement, transfer and DAO principal states separately, with source and freshness. (`inspect_account_state` in `agent/src/mcp/account-state.ts`; portfolio `AccountStatePanel`; fixture-tested per state.)
- [x] Add recovery alerts for missing audit/market data, deficits, unresolved payouts and indexer reconciliation. (`list_recovery_alerts` in `agent/src/mcp/alerts.ts`, recomputed per read so each alert clears when resolved; portfolio `RecoveryAlerts`; fire-and-clear tests per condition.)

  - Verified by fixture tests on disk: identical projection and digest for full replay, incremental ingest, restart and idempotent re-sync; the same receipt delivered again (also after its block was pruned) changes nothing, and the same receipt with a different payload is a conflict that requires reconciliation, never a second credit; replay after pruning rebuilds the same digest from the journal alone; health and reorg suspension survive a restart.
