## Context

One independently reviewed change in the arena redesign. See [coordination](../../README.md) and [product specification](../../../product-spec.md).

## Goals / Non-Goals

Deliver testnet integrations and observability and its acceptance scenarios without claiming unrelated work or unverified network support.

## Decisions

- Contract: [capability requirements](specs/arena-testnet-integrations/spec.md).
- Integration boundary: End-to-end acceptance depends on all implementation changes; research may run in parallel.
- Asset identity binds source chain/token, NEAR representation and custody domain.
- Keep custody verifier, oracle, signer, operator and player authorization boundaries explicit. Fixtures do not prove live execution. DAO governance and provider/finality choices remain OPEN.
- Read-only event indexing foundation (`agent/src/indexer/`). A read model over Valtrum NEP-297 logs with no write authority: it never submits, signs, allocates, confirms foreign payments or releases custody, and a retraction is a read-model operation only. A recorded source is a declared assertion of chain state, never verified finality; that provenance is preserved in every exported status.
  - Supported events (from the current `contracts/arena` emitter, standard `valtrum`, version `1.0.0`): `lifecycle_battle_created {battle_id, creator}`, `audit_updated {battle_id, community, result, evidence_hash, expires_at_ms}`, `lifecycle_deposit {battle_id, community, account_id, amount}`. The projection records creator, per-community credited totals (exact BigInt sums), audits and their deterministic latest-per-community, deposits, and per-event provenance with finality labels. It infers nothing absent from events: an audit result is not current-TTL validity, a deposit credit is not a payout, unknown history stays explicit, and unsupported future payout/DAO events are retained as unknown.
  - Source contract. An injectable `BlockSource` exposes source identity (network, `recorded`/`live`, optional genesis), a declared latest/finalized head, and `blockAt(height)` returning a block, a legitimate `skipped` height, `incomplete` coverage (never advanced over), or `beyond_head`. A recorded source and a future live adapter implement the same contract. Heights, amounts and on-chain integer ids are decimal strings compared as BigInt; a u64 is never rounded through a JS number, and a non-integer numeric value in a log is rejected (`unsafe_numeric`), not rounded, using lossless JSON parsing.
  - Identity and dedup. The emitter is the receipt executor, never a field inside the event; only allowlisted contracts and successful outcomes are accepted as state. The dedup key is `network | contract | receiptId | logIndex | dataItemIndex` (a transaction hash alone is insufficient). An exact duplicate is idempotent; the same identity with a different payload digest is a `conflict_payload` requiring reconciliation, never last-write-wins. Unrelated and other-standard logs are ignored; unknown event/version, wrong emitter, failed outcome and malformed/unsafe supported events are quarantined with bounded raw provenance and never silently applied.
  - Commit protocol and recovery. One versioned atomic snapshot (`arena-indexer-store-v1`) holding config, processed blocks (finalized prefix + provisional tail), the accepted-event journal, diagnostics and processed/finalized cursors; written temp-then-rename so a process crash before rename keeps the last committed state (not a claim of power-loss durability). Loads and commits validate journal payload digests, source/key provenance, unique events/blocks, parent ordering, finalized prefix, matching cursors, counters and health. These consistency checks detect corruption, not an operator rewriting both data and checksums. A single-writer lock prevents two runs overwriting the directory and never expires by age. `lockStaleMs` is deprecated and ignored for compatibility. After a crashed process, the operator must verify that all processes using this state directory have stopped, back up `state.json`, inspect it with read-only `status`/`replay`, then remove only `state.lock` before reopening; never remove the lock while another writer may be alive. The engine serializes overlapping `sync()` calls and `close()` drains the queue before releasing the lock, rejecting new syncs while closing. Reopening under a conflicting config (network, contracts, standard, schema/reducer version, anchor) is rejected. Corrupt or unsupported state is preserved and fails closed with a recovery message; missing state is distinct and starts empty. Bounded, documented limits; no retention/prune (an expired/old block is still evidence).
  - Fork algorithm and finality. On each sync the engine reconciles provisional blocks against the source by hash, rolls back orphaned provisional effects to the common ancestor, replays the canonical branch exactly once, and promotes finality only when the processed chain matches the source-declared finalized head. Missing/regressing/conflicting finality yields a visible pending/degraded/reconciliation-required status instead of substituting `latest` or a confirmation count; a conflict at or below the finalized boundary stops progression and preserves evidence rather than rewriting finalized state. The full replay of the committed journal at the committed finalized height reproduces the same normalized projection and digest.
  - Diagnostic retention does not determine unresolved conflict severity. `conflictBlocks` durably records source blocks with conflicting event identities, independently of the capped diagnostic detail list; later allowlisted-event diagnostics cannot downgrade reconciliation. `diagnosticOverflowBlocks` preserves the severity of discarded diagnostic details per source block, while `diagnosticsDropped` remains a historical counter. Safe rollback removes only markers attributed to orphaned provisional blocks. Finalized markers cannot be cleared by automatic rollback or a timeout. Older snapshots without marker fields reconstruct them from retained conflicts; a prior reconciliation status with dropped diagnostics is conservatively bound to the retained blocks when exact provenance was already lost. No destructive reset or manual status-edit command is provided.
  - Deferred (open): a live NEAR archival/indexing adapter and Robinhood EVM ingestion, custody/payout suspension on reorg (a backing/payout concern), UI fund-state display and broader recovery alerts, future contract projections, and full live end-to-end acceptance.

- RPC chain guard (`agent/src/chain-guard.ts`). `assertRpcChain` fails closed on a different, missing, malformed or unreadable chain id and never echoes the RPC URL. The foreign executor re-checks before every signature request and before every broadcast (no cached trust after a first pass); the custody verifier checks before accepting a source receipt and returns Pending with the reason. The audit liquidity reader keeps its separate mainnet check; the payout reconciler already checks per pass.
- Reference-token registry (`contracts/arena/src/reference_registry.rs`, `agent/src/reference-registry.ts`). Entries live in the arena contract, keyed by testnet chain and lowercase token; only the owner adds or removes them (exactly one yocto), and creators cannot. Entries must reference chain `4663`; a token has at most one entry and a reference token backs at most one token, so a change is an explicit remove then add. The entry hash is SHA-256 over the JSON array `[chain_id, token, reference_chain_id, reference]` (decimal strings, lowercase addresses), shared with the agent through a test vector; every change bumps the registry version and emits `reference_registry_updated` (not modelled by the indexer yet). `create_lifecycle_battle` refuses an unregistered or different declared pair and a registered token without its pair; existing battles keep their committed pair and the audit re-checks it every pass. The agent reads every page once per pass, recomputes each hash and refuses a malformed, incomplete or concurrently changed read; audit (`resolveAuditReference`) and scoring (`resolveScoringSubject`) resolve from that one snapshot. `AUDIT_REFERENCE_REGISTRY` is removed and startup fails if it is set. Deployments are fresh (no state migration). No entries are registered: the candidate tokens still need owner verification.

## Risks / Migration

Cross-chain operations must be idempotent, reconciled before retry and fail closed on missing evidence. Use isolated testnet deployments; legacy migration is out of scope.
