## Context

One independently reviewed change in the arena redesign. See [coordination](../../README.md) and [product specification](../../../product-spec.md).

## Goals / Non-Goals

Deliver testnet integrations and observability and its acceptance scenarios without claiming unrelated work or unverified network support.

## Decisions

- Contract: [capability requirements](specs/arena-testnet-integrations/spec.md).
- Integration boundary: End-to-end acceptance depends on all implementation changes; research may run in parallel.
- Asset identity binds source chain/token, NEAR representation and custody domain.
- Keep custody verifier, oracle, signer, operator and player authorization boundaries explicit. Fixtures do not prove live execution. DAO governance and provider/finality choices remain OPEN.
- Read-only event indexing foundation (`agent/src/indexer/`). A read model over Valtrum NEP-297 logs with no write authority: it never submits, signs, allocates, confirms foreign payments or releases custody, and a retraction is a read-model operation only. A recorded source is a declared assertion of chain state, never verified finality; that provenance is preserved in every exported status.
  - Supported events (version `1.0.0`, from the emitters on main). Standard `valtrum` (arena): `lifecycle_battle_created`, `audit_updated`, `lifecycle_deposit`, `backing_updated {battle_id, community, approved, evidence_hash, expires_at_ms}`, `lifecycle_representation_trust_changed {representation, trusted}`. Standard `valtrum_backing`: `late_deposit_recorded {battle_id, beneficiary, refund_address, units}`, `asset_suspended {reason}`, `asset_resumed`, `custody_attested`, `reconciliation_unresolved`, `operator_changed`, `resume_policy_changed`. Standard `valtrum_payout`: `signature_requested`, `signature_received`, `signature_failed` (stored as `payout_signature_*`, because the arena has events of the same names) and `payout_state_changed`. The backing and payout emitters write `data` as one object, the arena as an array; both are read as items. The projection records creator, per-community credited totals (exact BigInt sums), audits and latest-per-community, deposits, backing approvals, late deposits with their refund address, and per-contract trust, suspension, last attestation, operator, resume policy and payout state, with per-event provenance and finality labels. It infers nothing absent from events: an audit or backing approval is not current-TTL validity, a deposit credit is not a payout, a payout state is paid only when `confirmed` and finalized, and `reconciliation_unresolved` is lifted in the projection only by the next `asset_resumed` because the contract clears it silently.
  - Coverage rule. An event of a companion standard (`valtrum_backing`, `valtrum_payout`, `valtrum_player_policy`) or of the arena standard from an allowlisted emitter is either projected or quarantined as `unknown_event`, which degrades health. Nothing is dropped silently. Unmodelled on main (so degraded when emitted): the other arena events (proposal, approval, lock, settlement, deposit, claim, refund, halt, signature, treasury, DAO vote and release, escrow, reference registry, burn) and all player-policy events. Only a different standard (for example `war`, `furnace`) or a non-allowlisted emitter is ignored or recorded without a body. Router and Ref adapter events use standard `valtrum` and count as unmodelled if their accounts are allowlisted.
  - Source contract. An injectable `BlockSource` exposes source identity (network, `recorded`/`live`, optional genesis), a declared latest/finalized head, and `blockAt(height)` returning a block, a legitimate `skipped` height, `incomplete` coverage (never advanced over), or `beyond_head`. A recorded source and a future live adapter implement the same contract. Heights, amounts and on-chain integer ids are decimal strings compared as BigInt; a u64 is never rounded through a JS number, and a non-integer numeric value in a log is rejected (`unsafe_numeric`), not rounded, using lossless JSON parsing.
  - Identity and dedup. The emitter is the receipt executor, never a field inside the event; only allowlisted contracts and successful outcomes are accepted as state. The dedup key is `network | contract | receiptId | logIndex | dataItemIndex` (a transaction hash alone is insufficient). An exact duplicate is idempotent; the same identity with a different payload digest is a `conflict_payload` requiring reconciliation, never last-write-wins. Unrelated and other-standard logs are ignored; unknown event/version, wrong emitter, failed outcome and malformed/unsafe supported events are quarantined with bounded raw provenance and never silently applied.
  - Commit protocol and recovery. One versioned atomic snapshot (`arena-indexer-store-v1`) holding config, processed blocks (finalized prefix + provisional tail), the accepted-event journal, diagnostics and processed/finalized cursors; written temp-then-rename so a process crash before rename keeps the last committed state (not a claim of power-loss durability). Loads and commits validate journal payload digests, source/key provenance, unique events/blocks, parent ordering, finalized prefix, matching cursors, counters and health. These consistency checks detect corruption, not an operator rewriting both data and checksums. A single-writer lock prevents two runs overwriting the directory and never expires by age. `lockStaleMs` is deprecated and ignored for compatibility. After a crashed process, the operator must verify that all processes using this state directory have stopped, back up `state.json`, inspect it with read-only `status`/`replay`, then remove only `state.lock` before reopening; never remove the lock while another writer may be alive. The engine serializes overlapping `sync()` calls and `close()` drains the queue before releasing the lock, rejecting new syncs while closing. Reopening under a conflicting config (network, contracts, standard, schema/reducer version, anchor) is rejected. Corrupt or unsupported state is preserved and fails closed with a recovery message; missing state is distinct and starts empty. Bounded, documented limits, with retention below.
  - Fork algorithm and finality. On each sync the engine reconciles provisional blocks against the source by hash, rolls back orphaned provisional effects to the common ancestor, replays the canonical branch exactly once, and promotes finality only when the processed chain matches the source-declared finalized head. Missing/regressing/conflicting finality yields a visible pending/degraded/reconciliation-required status instead of substituting `latest` or a confirmation count; a conflict at or below the finalized boundary stops progression and preserves evidence rather than rewriting finalized state. The full replay of the committed journal at the committed finalized height reproduces the same normalized projection and digest.
  - Retention by checkpoint and prune (owner decision on #109, D30). After each sync, finalized blocks older than the retention depth behind the finalized head are folded into one checkpoint and dropped. The checkpoint (`kind: "summary"`, with a note saying it is not raw history) commits to the last pruned block (height, hash, parent), the cumulative pruned block count, the pruned event count and a digest over those events' `dedupKey:payloadDigest`, and chains the previous checkpoint's digest. The depth is `INDEXER_RETENTION_DEPTH` or `--retention-depth`, default 10000 finalized blocks, at least 1 (assumption below). Never pruned: provisional blocks (only finalized blocks are candidates); the journal, which holds every dedup key and the events the projection replays from; any block at or after the earliest conflict or integrity evidence; the finalized head. On load the store re-derives the checkpoint's event commitment from the journal and requires the first retained block to link to the checkpoint hash, so a removed dedup record or a broken link fails closed. After a restart the engine also asks the source for the checkpoint height once and requires reconciliation if the hash differs; a source that cannot serve it leaves the checkpoint verified by the parent link only. The block headers of the pruned range cannot be re-verified, which is why the checkpoint is a summary. Limit: journal growth is bounded only by `MAX_JOURNAL` (1,000,000 events), because dropping dedup keys could allow a duplicate allocation or payment; blocks no longer reach their limit.
  - Reorg suspension of confirmations (#109). A rollback of provisional blocks persists `reorgSuspension` (lowest retracted height, highest retracted height, retracted block and event counts). While it is set the status is at best `pending`, and `confirmations()` returns `confirmable: false` with no credits. It lifts when a sync promotes a finalized head at or above the highest retracted height on the canonical chain; partial finality does not lift it, and a restart keeps it. `confirmations()` otherwise returns finalized-only deposit credits and is also suspended while the status is `degraded` or `reconciliation_required`. It is a read model and never refunds, restores backing or sends a payout.
  - Runtime wiring (#109). `main.ts` runs the indexer when `INDEXER_ENABLED=true`, only over `INDEXER_RECORDED_CHAIN` (no live source exists; blocks and finality are fixture assertions) and logs that on startup. A failed sync is logged and isolated from settlement and payout passes. The audit report archive (`JsonFileReportArchive`) is injected as the lifecycle pass sink when `AUDIT_REPORT_ARCHIVE_ENABLED=true`, which requires `AUDIT_ENABLED=true`; the archive label is the arena contract id.
  - Diagnostic retention does not determine unresolved conflict severity. `conflictBlocks` durably records source blocks with conflicting event identities, independently of the capped diagnostic detail list; later allowlisted-event diagnostics cannot downgrade reconciliation. `diagnosticOverflowBlocks` preserves the severity of discarded diagnostic details per source block, while `diagnosticsDropped` remains a historical counter. Safe rollback removes only markers attributed to orphaned provisional blocks. Finalized markers cannot be cleared by automatic rollback or a timeout. Older snapshots without marker fields reconstruct them from retained conflicts; a prior reconciliation status with dropped diagnostics is conservatively bound to the retained blocks when exact provenance was already lost. No destructive reset or manual status-edit command is provided.
  - Deferred (open): a live NEAR archival/indexing adapter and Robinhood EVM ingestion, custody/payout suspension on reorg (a backing/payout concern), projections of the other arena events, and full live end-to-end acceptance.

- RPC chain guard (`agent/src/chain-guard.ts`). `assertRpcChain` fails closed on a different, missing, malformed or unreadable chain id and never echoes the RPC URL. The foreign executor re-checks before every signature request and before every broadcast (no cached trust after a first pass); the custody verifier checks before accepting a source receipt and returns Pending with the reason. The audit liquidity reader keeps its separate mainnet check; the payout reconciler already checks per pass.
- Reference-token registry (`contracts/arena/src/reference_registry.rs`, `agent/src/reference-registry.ts`). Entries live in the arena contract, keyed by testnet chain and lowercase token; only the owner adds or removes them (exactly one yocto), and creators cannot. Entries must reference chain `4663`; a token has at most one entry and a reference token backs at most one token, so a change is an explicit remove then add. The entry hash is SHA-256 over the JSON array `[chain_id, token, reference_chain_id, reference]` (decimal strings, lowercase addresses), shared with the agent through a test vector; every change bumps the registry version and emits `reference_registry_updated` (not modelled by the indexer; reported as `unknown_event` and degraded). `create_lifecycle_battle` refuses an unregistered or different declared pair and a registered token without its pair; existing battles keep their committed pair and the audit re-checks it every pass. The agent reads every page once per pass, recomputes each hash and refuses a malformed, incomplete or concurrently changed read; audit (`resolveAuditReference`) and scoring (`resolveScoringSubject`) resolve from that one snapshot. `AUDIT_REFERENCE_REGISTRY` is removed and startup fails if it is set. Deployments are fresh (no state migration). No entries are registered: the candidate tokens still need owner verification.

- Account state and recovery alerts (#79, D27). Read-only; no write authority.
  - **`inspect_account_state`** (account-scoped) returns three separate lists, each item with source and observation time:
    - **entitlements:** per backing, from `entitlement_of`;
    - **transfers:** payout records with their display stage, where only `confirmed` is paid;
    - **DAO principal:** position, vote status from `get_lifecycle_disposition`, the account's return release, and the backing's `get_escrow_disposition` (returned, burn pending, burn confirmed).
  - **`list_recovery_alerts`** recomputes alerts on every read, so there is no stored alert to go stale:
    - a missing or expired audit on an open battle;
    - missing market data (a locked round more than 5 minutes past its end without a winner);
    - a backing deficit, suspension or unbalanced ledger;
    - a payout that is reverted or needs reconciliation;
    - an indexer that needs reconciliation, is degraded, or is stale (no committed sync for 10 minutes).
  - **Indexer health** comes from the indexer's `state.json` (read-only, `INDEXER_STATE_DIR`), and its modification time is the last sync. A missing or unreadable state is reported as degraded, never as healthy.
  - **Web:** the portfolio page shows both panels. The account panel takes a read-session token, because the wallet integration has no NEP-413 `signMessage` yet.

## Risks / Migration

Cross-chain operations must be idempotent, reconciled before retry and fail closed on missing evidence. Use isolated testnet deployments; legacy migration is out of scope.
